# 机械动力&精致存储：兼容与改善（rs_create_compat）

**把机械动力的「序列装配」接进精致存储的自动合成：在 RS 里下单，由序列执行仓驱动 Create 的机器一步步加工，产物自动回到网络。**

## 一、这个模组做什么

机械动力的「序列装配」是一套多工序产线：一件在制件被反复投料、冲压、切割、机械手装配，走完若干步之后才变成成品，而且成品可能带概率、还会掉废料。精致存储的自动合成则会替你排队、算料、补料 —— 但它只认「样板：一份投入 → 一份产出」，并不知道一件在制件现在走到了第几步。

本模组就是这两者之间的那层翻译：

- **在精致存储里下单就行。** 产物写进「序列装配总样板」并放进序列装配样板库之后，它就和你普通的自动合成样板一样出现在终端里；下单后 RS 负责抽料、补料、排任务。
- **机器由执行仓驱动。** 贴着 Create 机器摆一台「序列执行仓」，把对应那一步的「单元样板」放进去，它就会认领网络里的原料与半成品、按时喂给面前的机器，再把加工完的东西收回来。
- **产物回网。** 成品回到 RS 网络并计入任务交付；半成品（过渡件）直接回网，交给下一步的执行仓继续加工。
- **概率与废料被认真对待。** 主产物不是必得的配方会被正确处理：精密构件的产物池权重是 `120 / 8 / 8 / 5 / 3 / 2 / 2`，界面上显示的主产物概率为 81%、废料各自显示自己的百分比，投料也按概率分批递进；废料有独立的类别，可以被单独勾选回收。
- **卡住了会告诉你。** 缺料、执行器掉线、下游推不进去、长时间无进展，都会被看门狗识别，挂起任务并在自动合成监视器里给出一条横幅和「继续 / 更换机器」按钮。

除序列装配之外，模组还提供了一批配套机器：蓝图加农炮装填器、归流缓存仓、资源定量保持器、范围充电器、通用储存磁盘、分隔框架 / 伪装框架，以及可在多种终端界面之间切换的高级远程多功能终端。

## 二、核心概念

| 概念 | 一句话解释 |
| --- | --- |
| **序列装配总样板**（`sequence_assembly_pattern`） | 整条产线的「一张脸」：写清起步原料、产物、废料、总步数。把它放进样板库，RS 就认得这条自动合成。 |
| **序列装配单元样板**（`sequence_unit_pattern`） | 只描述**一步**：名字、配方类型（例如 `create:pressing`）、要不要输入原料、输入什么。它是放进执行仓的东西。 |
| **序列装配样板库**（`sequence_assembly_executor`） | 总样板的容器兼「类自动合成仓」。放入总样板并接入网络，这张样板立刻注册成网络里的自动合成样板；它不对着机器，也不驱动任何产线。 |
| **序列执行仓**（`sequence_execution_chamber`） | 真正干活的机器，紧贴 Create 机器摆放（六向朝向，可以朝上 / 朝下）。存取单元样板（54 格），自动供料、自动收回产物。 |
| **序列装配样板终端**（`sequence_pattern_terminal`） | 玩家编辑入口：导入 Create 序列装配配方（JEI 里点 `+`）、为每一步指派机器、生成总样板与单元样板。流程本身**只读**，避免随手改动。 |
| **单元样板管理舱**（`unit_pattern_manager`） | 把网络里各执行仓的单元样板按执行仓（成链后合并）分组列出来统一管理；总样板仍归「自动合成仓管理器」管。 |
| **输入总线 / 输出总线**（RS 的 Importer / Exporter） | 接上执行仓之后自动变成「延长型」：输出总线负责把原料与中间产物从执行仓推给面前的机器，输入总线负责把执行仓里的东西收进网络。 |
| **类别** | 总线上可勾选的资源分类，共六组：**原料**（起步原料）、**输入时原料**（各步加工途中投进去的东西）、**流体**、**中间产物**、**成品**、**废料**。 |
| **成链** | 多台同配方类型的执行仓沿箭头首尾相接 = 一个「逻辑执行仓」。容量与单元样板合并，链上的名字与配方类型改任意一台即整链生效（扩容用）。 |
| **中间产物缓存仓**（`intermediate_cache`） | 27 个磁盘槽位，插入 RS 储存磁盘后成为**全网执行舱共用**的中间产物临时存放点；多台缓存仓自动合成同一个池子。 |
| **共享机器排队** | 一台机器被多条配方共用时，按「谁先下单谁先站这台机器」排队；先下单的那条做完（或暂时没件可做）才让给下一条。 |
| **中间产物优先复用** | 一个开关。打开后，要开新件时若网络里已有该配方某一步的中间产物，就把它当起点，跳过前面已经做过的工序。 |
| **分隔框架 / 扳手断开** | 两种把线缆「隔离」的手段：分隔框架套在线缆或流体管道上，把它与邻居的连接冻结在套上那一刻；机械动力扳手则可以直接在接缝处断开 / 恢复一段线缆连接（默认档位 `seam`）。 |
| **快速拆卸** | 潜行加右键、手持扳手，直接拆掉本模组的方块（与精致存储自己的机制一致）。 |
| **剪贴板批量配置** | 手持机械动力剪贴板右击总线复制配置、左击粘贴到这一条、潜行加左击粘贴到同一条线缆簇里的全部同种总线。 |

## 四、快速上手

1. **造一条 Create 产线。** 冲压机、机械手、注液器、置物台等，按你想要的那条序列装配配方摆好。
2. **贴执行仓。** 在机器旁边放「序列执行仓」。它的朝向面默认就是**原料输入面**（自己主动喂给机器的那一面）。
3. **给执行仓设身份。** 打开执行仓的「配置」，设好**配方类型**（例如 `create:pressing`）和**名字**。单元样板只有在配方类型与本仓完全一致时才放得进去。
4. **做样板。** 放一台「序列装配样板终端」，在终端的样板输入槽里放一张精致存储样板（`refinedstorage:pattern`）作为生成耗材。用 JEI 的 `+` 导入一条 Create 序列装配配方，或在界面里导入。
5. **为每一步指派机器。** 在流程编排里点某一步，挑一台执行仓。每一步由总样板记下的机器位置唯一决定。
6. **生成样板。** 点「生成样板」：得到 1 张**总样板**，同时每一步各得到 1 张**单元样板**（写入终端的单元样板库）。总样板槽「只出不进」，要再生成新的必须先把现有的拿走。
7. **分派单元样板。** 把每一张单元样板放进对应那一步的执行仓（手持右键放入，或在「执行舱单元样板汇总」子界面里点「存入」）。
8. **注册总样板。** 放一台「序列装配样板库」并接入 RS 网络，把总样板放进它的槽里 —— 这一刻起，这张产物就是网络里的一条自动合成。
9. **接总线。** 用 RS 线缆把输入总线 / 输出总线连到执行仓上（它俩都会自动变成「延长型」，界面变成类别勾选）。也可以不接总线，改用执行仓自己的「面配置」，逐面设置原料输入 / 产物输出 / 中间产物输出。
10. **放一台中间产物缓存仓**（强烈建议），插上 RS 储存磁盘，让半成品有地方落。
11. **下单。** 在任意 RS 终端里下单总样板的产物，然后在「自动合成监视器」里看进度。

## 五、界面与操作要点

### 序列装配样板终端
- 导入 Create 序列装配配方：JEI 配方页面按 `+`（只对「序列装配」类别生效），或使用界面内的导入。
- 流程编排**只读**：机器的指派能改，流程本身由配方决定，不给你手动改坏的机会。
- 每一步可开关「生成时跳过重复单元样板」；产物与废料的数量、概率可单独配置。
- 生成耗材取自终端内的**样板输入槽**（精致存储样板）。
- 左键「单元样板库」标题打开**执行舱单元样板汇总**：逐台显示执行仓、配方 id 与它持有的单元样板，并提供「取回 / 存入」。
- 网络里没有中间产物缓存仓时，终端会提示「本流程中间产物（终端看不到）」。

### 序列执行仓
- 主界面标题行有「配置」（名字 / 配方类型 / 成链状态）与「面」两个按钮，输出模式在「面输出」与「总线输出」之间切换。
- **面配置**四档：无、原料输入（推给相邻机器）、产物输出（从相邻容器抽产物进本仓）、中间产物输出（从相邻容器抽过渡件并直接回写网络）。默认机器朝向面 = 原料输入。
- 执行仓与自动合成仓一样是**只出不进**的：外部物流不能往它里面塞东西，只能在输出面 / 中间产物输出面把东西抽走。

### 总线（延长型）
- 输入 / 输出总线用 RS 线缆连到执行仓后自动进入延长型，界面换成「类别详细配置」：配方标签页 + 六组分类（原料 / 输入时原料 / 流体 / 中间产物 / 成品 / 废料）勾选，可搜索、可折叠、可「全部清空」。
- 类别条上的「普通」按钮可以把一条总线主动降回普通总线界面（之后可点「恢复」重新按线缆连通自动判定）。
- **过滤槽优先**：输入 / 输出总线的 RS 过滤槽里**放了东西**时，这条总线**优先按普通总线**处理（过滤槽为空时照旧按延长型）。判据是 RS 自己的过滤容器，现算不缓存，改过滤槽会立刻翻转；「界面走哪一套」与「搬运走哪条路」共用同一个判据，因此不会出现「界面看着是普通、实际还在按类别搬运」。
- 归属规则：一条总线够到**恰好一条链**时归属成立。够到**两条以上不同的链**（不论距离）才判为「归属未确定」并**停用这条延长型**，同时弹出横幅。**「这一趟还没扫完」不再等于停用** —— 搜链是可续扫的，只有整趟扫完才发布结论，续扫期间沿用上一次的完整结果；因此很长的线缆上排在后面的总线不会再被静默漏掉，也**不会**因为「哪些区块已加载」不同而给出不同答案。界面上的「显示可达区域」会用半透明叠加层标出它够到的执行仓与线缆段。
- 同一类别可以被多台输出总线同时选中，由执行仓按轮询在它们之间均分。

### Jade 总线提示（可选依赖）
瞄准输入总线 / 输出总线时，Jade 提示会告诉你三件事：

- 这条总线**绑定到哪台执行舱**；
- 它**此刻负责什么** —— 按类别分节列出（原料、输入时原料、流体、中间产物、成品、废料）；
- 输入总线处于**全自动**时额外强调这一点。

显示方式由配置项 `jadeBusTooltipMode` 控制：默认 `always`（一直显示），可以切成 `shift`（按住 Shift 才显示，没按住时只留一行提示）。每节最多列三件代表物，超出只写一个「…」，不写数量。没装 Jade 时这一节完全不存在，其余功能不受影响。

### 用 Create 剪贴板批量配置总线
一条一条手动配总线太麻烦，可以借 Create 的剪贴板一次配一片。手势与 Create 自己的「复制 / 粘贴方块配置」约定一致：

| 手势 | 作用 |
| --- | --- |
| 手持剪贴板**右击**总线 | 复制这条总线的全部玩家配置（RS 过滤槽与模糊模式、本模组的类别勾选、「全自动收回」、强制普通总线） |
| 手持剪贴板**左击**总线 | 把配置粘贴到**这一条**总线 |
| **潜行**加左击总线 | 粘贴到**同一条线缆簇里的全部同种总线** |

边界：只走同一条线缆簇（扳手断开的接缝与被分隔框架冻结的接缝都算断），只改同一种总线，最多 64 台，绝不跨维度；种类与版本不符时一个字节都不写。载荷只替换**本模组那一段键**，不会抹掉别的模组已经复制进去的内容；读剪贴板、校验与写入全部在服务端完成。

### 快速拆卸（潜行 + 扳手右键）
精致存储自己的方块、线缆之类，按住 Shift 加右键、手持扳手可以直接快速拆掉；本模组现在也一样。

- 覆盖本模组注册的**全部 14 个方块**（11 台机器加 3 个框架方块）；判据是注册表命名空间，因此将来新增的方块自动生效。
- 与精致存储同机制：扳手判据沿用工具标签，不潜行时照旧放行原有右键交互（界面照常打开），权限不足时沿用精致存储自己的提示，音效一致。
- 拆除顺序是「先产出掉落物、再移除方块」，因此本模组在移除方块时做的内容物结算（受 `/rs_create_compat blockcontent` 档位控制）与机器集群内容移交都不会被跳过。

### 范围充电器与饰品栏
范围充电器会为玩家身上的物品充电，覆盖**主背包、快捷栏、盔甲、副手与 Curios 饰品槽**。饰品槽不递归容器内的容器（精致背包之类不再往里翻），也不是每 tick 扫 —— 间隔由配置项 `rangeChargerCuriosScanInterval` 控制（默认 5 tick）。已满电的物品会被跳过，同一次扫描不会重复充同一件。

### 自动合成监视器
- 卡住的任务会挂起；横幅会说明原因：缺少材料、执行器掉线、输出阻塞、长时间没有任何进展。
- 监视器里提供「继续」「挂起」「更换机器」「缺料处置（缺料·挂起 / 缺料·等待）」。
- **挂起后不会自动恢复**，必须在监视器里点「继续」。
- 按钮的显隐只由服务端下发的动作位与界面几何决定：只要任务还存在且没被 RS 回收，主槽位（挂起 / 继续）必定有一个按钮；选中一条本地还没有快照的任务时，客户端会**自动补拉一次只读快照**。按钮行与精致存储原生的取消按钮同一行同高，放不下时整排收起。
- 只有**本模组序列装配链真正驱动**的任务才会被自动挂起；普通任务的产物恰好也在本模组样板库里时**不会**被牵连。普通任务即便被手动挂起，超限之后也**不会**被自动取消。

### 序列装配样板库
- 库里的**总样板会一直显示它合成什么物品**，与精致存储自动合成仓里那种「默认就显示产物」的样子一致，不需要按 Shift。


### 快捷键

| 按键 | 作用 |
| --- | --- |
| `G` | 打开高级远程多功能终端（需要终端在主手、背包或饰品槽里） |
| `H` | 切换分隔框架显示（需要佩戴护目镜） |

### 高级远程多功能终端
可在五种界面之间切换：合成终端、样板终端、自动合成仓管理器、自动合成监视器、序列装配样板终端。普通版 / 满电版 / 创造版三种形态；对准无线信号发射器或网络节点右键可绑定。

## 九、已知限制与注意事项

1. **样板是生成时的静态快照。** 改完流程、换了机器、或升级模组之后，要让新配置生效，必须**重新生成**总样板与单元样板。而且总样板槽是「只出不进」的：槽里有样板时「生成样板」按钮会置灰，得先把旧的取走。老存档的样板不带「候选组」（例如列车轨道的铁粒 / 锌粒二选一），需要重新生成一次才能带上。
2. **面输出模式尚未补齐安全闸门。** 上游技术文档明确记录：`FACE` 输出通路缺少 `BUS` 通路那一整套闸门，起步原料在「已经被机器转成过渡件」时可能被再次投放，产生多开一件在制件（表现为多余的中间产物）。实机验证走的是总线输出模式，切换到面输出之前请先评估这一点。
3. **总线归属未确定时会停用整条延长型。** 一条输入 / 输出总线只要够到**两条以上不同的链**（不论距离远近），就会被判为「归属未确定」并停用，同时弹横幅。解决办法是用分隔框架、扳手断开把线缆隔离。**「这一趟还没扫完」不再会触发停用** —— 搜链是可续扫的，只有整趟扫完才发布结论，续扫期间沿用上一次的完整结果；因此很长的线缆上排在后面的总线不会被静默漏掉，装了新的区块之后结论也不会翻转。线缆规模极大、撞上单趟硬上限时，模组会照实标成「未穷尽」并留一条可核对的日志，不会静默丢弃。
4. **共享机器排队读的是「下单时刻」。** 它取 RS 任务里的 `startTime`（墙上时钟毫秒）：同一毫秒内的两笔订单按配方 id 字典序打破平局 —— 这是确定性次序，但不等于真实先后；服务器改过系统时间、或从别的存档导入过任务时，先后可能与直觉不一致；读不到下单时刻的配方**不参与独占机器**（排在最后）。
5. **中间产物要看得见，得先有缓存仓。** 网络里没有中间产物缓存仓时，中间产物只会落回网络与执行仓内部存储，样板终端里会提示「本流程中间产物（终端看不到）」并建议你补一台缓存仓。
6. **挂起不会自愈。** 掉线、缺料、输出阻塞、无进展都会挂起任务，而恢复的唯一入口是玩家在自动合成监视器里点「继续」。点「继续」只是清除挂起并让检测器重新计时，仍然缺料时会再次挂起。
7. **终端的「类别详细配置」还缺一个输入框。** 上游待办里记为未完成项（用户尚未明确输入框用途）。
8. **气体暂未纳入「阻塞」判定。** 归流缓存仓的阻塞能力只覆盖物品与流体；气体在 RS 2.0 的资源体系里没有独立资源类型，相关入口目前是预留状态。
9. **终端界面的候选缓存只写不清。** 若首帧在配方 / 槽位未就绪时算出空表，会以空结果缓存整局；当前有「样板落盘候选」兜底，影响已被削弱，但仍记为健壮性隐患。
10. **执行仓只出不进是刻意的。** 它的对外物流能力被包装成「只出」视图，外部管道 / 漏斗塞不进去；要往产线里送料，请走输出总线或面配置的原料输入面。
11. **「搜索未穷尽」不等于「没问题」。** 线缆搜链撞上单趟硬上限（4096 格）时会照实标成「未穷尽」并发布一份结果、留一条可核对的日志，不会静默丢弃。这种规模的线缆网络本身就很难维护，建议用分隔框架把拓扑切开。
12. **结构缓存的失效源是粗粒度的。** 与结构无关的方块变化（例如远处放一块石头）也会让下一次读取重建一次结果。重建上限是 8 台以内的小推导，这是「宁可多失效、绝不漏失效」的刻意取舍。缓存只活在内存里、不写进存档，也不缓存存货、机器忙闲、拒收与在途计数这类动态量。
13. **剪贴板整簇粘贴有上限。** 只走同一条线缆簇、只改同一种总线、最多 64 台、不跨维度；超出范围的会被跳过，不会部分写入。
14. **Jade 提示会截断。** 每节最多列三件代表物，超出只写一个「…」，不写数量 —— 这是刻意的（提示要放得下），想看全请打开总线界面。
15. **饰品槽充电有节流。** 默认 5 tick 扫一次，「放进去之后立刻满电」不会发生，延迟不超过一秒；想更快可以把 `rangeChargerCuriosScanInterval` 调小（最小 1）。
16. **1.1.0 的多数修复以源码交叉验证与模型推演为依据，不等同于实机验证。** 自检脚本里对总线分配、预留模型、结构缓存与线缆搜链这几处都明确写着「没有实机验证」。每一条断言都能被源码事实、模型反例证伪，而且模型与实现逐字同构，但它确实不等于在真实世界里跑过 —— 大规模线上产线升级前建议先跑一个小批量订单。

## 十、常见问题（FAQ）

**Q1：下了单，但机器一动不动、也不消耗原料。**
按顺序排查：
1. 总样板是否已经放进「序列装配样板库」的槽里？没放等于网络里根本没有这条自动合成。
2. 检查有没有「**总线未配置：已暂停，不会消耗原料**」这条横幅 —— 它点名了是第几步缺输入 / 输出总线配置。
3. 每一步的执行仓是否在线、配方类型是否匹配？终端里点该步可以重新指派；监视器里也有「更换机器」。
4. 敲 `/rs_create_compat diag` 导出快照，再看 `run/logs/latest.log` 里的 `push_stalled` 行：`reason=STEP_OWNER_MISSING` 表示某一步没有任何在线执行仓认领，`reason=DESTINATION_REFUSED` 表示下游机器拒收。
5. 单元样板是否放进了执行仓？请用 `/rs_create_compat diag` 的 `chambers` 分组确认每台仓里的单元样板与它的配方类型。

**Q2：总线界面变成了普通的输入 / 输出总线界面，类别勾选不见了。**
说明这条延长型的**归属未确定**，被自动停用了（界面上会有横幅）。原因是它的线缆簇够到了**两条以上不同的链**。
- 用「显示可达区域」看清它够到了哪些执行舱；
- 用**分隔框架**套住要隔离的那段线缆 / 管道，也可以用**扳手在接缝处断开**（默认档位 `seam`；配置可切到 `face` 逐面断开）；
- 也可以直接把那几台执行仓分开放；
- 如果你本来就想把它当普通总线用，点类别条上的「普通」即可，之后还能点「恢复」重新自动判定；
- 如果是因为**过滤槽里放了东西**而变成了普通总线，这是「过滤槽优先」规则在起作用：把过滤槽清空就会回到延长型。

> 从 `1.1.0` 起，「搜链这一趟还没扫完」**不再**会造成停用。以前因为线缆太长、总线太多而被误停用、被退回普通的总线，升级后会自己恢复正常，不需要拆线重连。

**Q3：监视器弹出「输出阻塞：第 N 步 …，任务无法继续；到监视器点继续」。**
这意味着下游工位推不进去，通常是机器上还压着东西：
1. 看那台机器（或置物台）上是不是压着**废料**或另一件在制件；
2. 清掉堵住的东西（废料可以靠输出总线的「废料」类别或归流缓存仓回收）；
3. 回到自动合成监视器点「继续」—— 它不会自己恢复；
4. 想减少这类阻塞，可以打开 `/rs_create_compat refill machines`，让本仓喂着几台机器就发几份料，避免一次灌太多。

**Q4：中间产物越堆越多，终端里还看不到它们。**
1. 放一台**中间产物缓存仓**并接入网络，插上 RS 储存磁盘（27 个盘位；多台缓存仓自动合成一个池子）。终端里那些「看不到的中间产物」条目会立刻出现。
2. 打开执行仓界面看内部存量，确认半成品是压在仓里还是压在机器上。
3. 打开 `/rs_create_compat reuse on`：开新件时优先取网络里已有的中间产物当起点，不再从第一步重跑一遍。
4. 打开 `/rs_create_compat supply target`（默认档），让缺料自动合成补齐。

**Q5：我把某一步的机器换掉了（或者拆了重放），现在那一步不工作了。**
样板记的是机器位置，换机器后要重新指派：
1. 手持那张**总样板右键空气**，打开「总样板机器绑定」，选中那一步再点「改绑机器」（改绑会一并把该步的单元样板搬到新机器）；
2. 或者回终端里点该步重新指派；
3. 改完之后建议重新生成一次总样板与单元样板，确保线上跑的配置与你看到的一致（注意总样板槽只出不进，先取走旧的）。

**Q6：单元样板放不进执行仓。**
三个条件同时满足才能放：
1. 它必须是**序列装配单元样板**（原版 RS 样板一律拒收）；
2. 该执行仓必须已经设好**配方类型**与**名字**；
3. 样板自带的配方类型必须与该仓绑定的配方类型**完全相等**。
链上的名字与配方类型由链首唯一持有，所以「在链上任意一台改」等于改整条链。

**Q7：要拆掉机器，但里面还有东西，怕丢。**
先决定内容物去向：`/rs_create_compat blockcontent network`（写回网络，没网络就自动存在方块里）、`drop`（掉落出来，默认档）、`block`（存进方块物品，重新放下原样恢复）。执行仓、样板库、中间产物缓存仓等都遵循这一档设置。

## 十一、出问题时怎么取证

- **一键快照**：`/rs_create_compat diag`。导出位置 `run/rscc_diag/<时间戳>/snapshot.json`，同时覆盖 `run/rscc_diag/latest/snapshot.json`。里面有执行仓的存量与认领的步、总线的已勾选类别与链接到的执行器、每个方块实体的完整 NBT、每个容器的逐格内容、通用储存磁盘的资源表、玩家手持物、缺料与挂起记录、守恒账本等。只读、幂等，产线运行中随时可导。
- **日志**：`run/logs/latest.log` 里是本模组的结构化诊断行；`run/logs/debug.log` 里有精致存储自己的任务行（`Created task …`、`Task … state changed …`）。
- **日志前缀**：

| 前缀 | 内容 |
| --- | --- |
| `[rscc-build]` | 构建指纹（git revision / 分支 / 编译时间 / 源码数 / MC / NeoForge / Java），每次启动恰好一行 |
| `[rscc]` | 诊断锚点（会话起点、缺料与补发档位）；`[rscc-diag]` 是快照的分节标记 |
| `[rscc-assembly]` / `[rscc-trace]` | 序列装配事件流与端到端追踪 |
| `[rscc-ledger]` | 守恒账本：对平时零输出，失衡才告警 |
| `[rscc-dedupe]` | 单元样板查重判定：某一步为什么被跳过、跟谁重复 |
| `push_stalled` | 「推不动」的原因（机器满、或者某步没有执行仓认领） |

诊断日志**默认关闭**（`devLogs` / 配置项同名），需要时用 `/rs_create_compat devlogs on` 打开（旧写法 `/rs_create_compat assemblydebug on` 等价），不需要重启。关闭状态下 WARN 与 ERROR、启动指纹 `[rscc-build]`、会话锚点、`diag` 导出与玩家操作的直接后果都照常输出。
