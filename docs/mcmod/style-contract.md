# MC百科资料页写作契约（本批次硬约束）

> 来源：`_skills/mcmod-page/SKILL.md`（MC百科页面编写技能包，MIT，zgxhzhr/mcmod-page）
> 与论坛《MC百科主站编辑规范》<https://bbs.mcmod.cn/thread-646-1-1.html>。
> 本文件是"写手必须遵守的最小集合"，与 SKILL.md 冲突时以 SKILL.md 为准。

## 1. 交付物形态

每条资料正文写成 Markdown（`body.md`），由 `tools/mcmod_gen.py` 统一转成百科 HTML 片段。
**不要手写 HTML**；不要写 `[hN=]`（除非正文超过 1200 字且确实需要分节，见 §4）。

## 2. 资料页正文的结构（固定顺序）

1. **首段：是什么 + 在本模组里承担什么职责。** 一句话说清它属于哪条链路（序列装配 / 归流缓存 / 框架 / 终端 / 磁盘……），不要复述模组简介。
2. **用途 / 用法**（加粗小标题段落）：交互方式（左右键、潜行、界面按钮、快捷键）、能做什么、不能做什么。
3. **参数**（仅当确有多项数值/档位时）：两列以上的表格，左列名称加粗，右列说明；不超过 8 行。
4. **获取**：合成、创造模式、终端生成等；写不出来就写"仅创造模式可获取"或"生存获取途径待确认"。
5. **注意**（可选）：限制、已知问题、前置条件。
6. 若该物品/方块只在 **1.2.0**（开发版）加入，在首段末尾标注「（1.2.0 起）」，并在正文里避免出现"新版/旧版"字样。

**读者对象**：玩过精致存储 2 与机械动力、但不了解本模组的玩家。第一次出现的本模组专有名词（单元样板、总样板、执行仓、类别、成链……）必须就地解释一句。

## 3. 语言与格式红线（审核会打回）

- 只写客观事实。禁"我觉得/个人认为/小编"、禁"貌似/据说/好像"、禁颜文字与 emoji、禁脏话、禁"！！！/。。。"这类标点堆叠。
- 禁"PS./PSS./注："前后缀，注解融进正文。
- 禁分割线（`---`、`***`、图片/字符串拼的分割线）。
- 禁 `<code>`、`<blockquote>`；代码/指令总长超过 500 字节必须进代码块。
- **标点**：每句以句号收尾；中文用全角标点；数字与单位之间加半角空格（`5000 万 FE`、`32 FE/t`、`3×3`）；范围用 `~` 或 `至`，条件符号用 `≥ ≤ > <`。
- 禁"新版/旧版/老版本"，一律写具体版本号（`1.0.0`、`1.1.0`、`1.2.0`）。
- 禁冗余句（"欢迎补充""介绍就到这里"）。
- 正文里不出现行号、`文件:行号`、`（L1234）`、反引号包围的代码标识符（注册名除外，走字段）。参数名如 `devLogs` 写成普通文本或代码块；**正文中的配置键与指令**放行内普通文本即可，不要用反引号（转换器会输出为纯文本）。
- 专有名词一律以 `src/main/resources/assets/rs_create_compat/lang/zh_cn.json` 为准（中文名、tooltip、help 文案）。**禁止**从 Java 标识符直译。
- 数值（容量、耗电、范围、上限、概率、tick）必须能在 `facts.md` 里指回文档或代码；查不到就删掉该数值，不要估算。
- 同类资料不重复大段文字：磁盘 9 档只写在父资料「通用储存磁盘」，子资料用「引用」。
- 不写服务器宣传、不写站外"具体玩法请看 XX"。

## 4. 标题层级

- 本批 28 条资料**默认不用 `[hN]` 标题**，用加粗小标题段落（`**用途**`）。
- 仅当正文超过约 1200 字（例如「通用储存磁盘」父资料）才用 `[h2=…]`，并且：
  - 标题单独一行写成 `## 概述` 这样的 Markdown 二级标题；
  - 不加数字编号（百科目录自动编号）。

## 5. 链接

- 指向**已存在**的百科资料时用：`[序列执行仓](https://www.mcmod.cn/item/1014424.html)`。
- 指向**本次新增、尚无 id** 的资料时，写纯文本名称，不造 URL（建好后再由 Lead 补链接）。
- 站外链接只允许作者/官方来源（如 GitHub 仓库），且必须同时给出完整介绍，不能只有链接。

## 6. 事实与版本口径

- 代码现状 = `1.2.0-beta.8`（`gradle.properties`）；公开版本 = `1.0.0`、`1.1.0`。
- 本批 8 个新增资料属于 **1.2.0 开发版**，正文首段标注「（1.2.0 起）」；提交策略见 `decisions.md`。
- 素材优先级：`README.md` / `TECHNICAL_HANDOFF.md` / `CHANGELOG.md` / `docs/*.md` > `lang/zh_cn.json` 的 tooltip / help > 代码。文档与代码冲突时以代码为准，并在 `facts.md` 里记录冲突。
- **禁止读大量代码**：优先在 docs / CHANGELOG / lang 里找；只有数值对不上时才定点 grep 并用行号记录。

## 7. 每条资料必须附带的两个文件

`body.md`：正文（Markdown，按 §2 结构）。
`facts.md`：证据表，逐条列出正文里的每个事实/数值与出处（`文件:行号` 或 `lang 键`）+ 截图需求（见下）。

`facts.md` 固定表头：

| 正文断言 | 出处 | 备注 |
