# 第 112 轮：每区域过滤标记「随身带」+ 独立标记界面（1.2.0-beta.14）

> 用户原话（第 112 轮实机反馈，语音转写）：
> 「而且现在貌似无法正常的单独给某一个区域标记嗯就非得把这个标记放在方块中进行吗这样子感觉很麻烦
>  而奇幻的时候更麻烦感觉」
> （「奇幻」是语音识别把**切换**听错的产物；同一批反馈里前一句是「而且那个区域呢这个过滤器在这一个
>  方块里面进行设置而且这样子有点不太直观」。）

## 1. 问题是什么（真因，不是猜）

第 101 轮把「每个区域各自的过滤标记」存在**方块实体**上，键 = 区域序号：

| # | 后果 |
|---|---|
| ① | 想给某个区域配标记必须**走到机器前 → 把选定器插进槽 → 进机器界面 → 用 `< >` 切到那一行**；手里拿着选定器时什么都做不了（= 用户说的「非得把这个标记放在方块里」） |
| ② | 区域序号一变（删 / 重排）过滤器就套到**别的区域**上 |
| ③ | 换一台机器 / 把选定器拆走 ⇒ 过滤全丢 |
| ④ | 区域列表里的「编辑过滤」只是**切机器的 48 格窗口上下文并退回机器界面** —— 玩家仍然只能在方块里配（= 「切换的时候更麻烦」） |
| ⑤ | 快照里的每区域过滤图标按**原始下标**去查「按可用位次存」的表：一旦有区域因超限 / 几何非法被排除，图标就会串到别的区域 |

另外还有两个入口问题：打开区域列表只有「潜行 + 右键空气」一个入口，而玩家站在基地里几乎总是**对着方块**，
潜行右键会落到「取消框选 / 提示」分支 ⇒ 列表根本打不开，只能走机器界面。

## 2. 这一轮怎么改

### 2.1 数据搬家：`support/AreaMarks`（新）

每区域过滤标记改为存在**区域选定器物品**的 `CUSTOM_DATA` 上：

```
RsccAreaMarks: {
  Marks: [ { Area: [minX,minY,minZ,maxX,maxY,maxZ], Entries: [ <ghost 标记>... ] }, ... ]
}
```

- **键 = 六坐标几何**（`Area#withName(null)`）：区域改名 / 重排 / 复制**不会串位**（顺手修掉 ②）；
- **编码复用**机器「匹配区」的同一份标记编解码（`CollectionCacheBlockEntity#encodeMarkerTag/decodeMarkerTag`
  改为 `public static` 后直接调用）—— 物品 / 流体 / 数据组件 / 数量门槛 / 标签匹配全部沿用同一套语义，
  不存在第二套匹配规则；
- 上限复用 `MATCH_CAPACITY`（单区域）/ `AreaSelection.ABSOLUTE_MAX_AREAS`（区域数），读档逐条校验、
  解码失败直接跳过（**绝不抛异常**）、超限截断；
- 空表 = 删除整条记录（物品上不留 `{}` 噪声）；`prune` 只剪「已经不在区域表里」的几何；
- `migrateByIndex` 负责旧档一次迁移：把「区域序号 → 标记」翻成「几何 → 标记」（越界序号丢弃）。

### 2.2 方块实体：读写全部改走物品（旧档自动迁移）

`AdvancedCollectionCacheBlockEntity`：

- 旧字段 `Map<Integer, List<MarkerEntry>> areaFilters` **删除**，只剩 `legacyAreaFilters`（迁移缓冲）；
- `migrateLegacyAreaFilters()`：槽里有选定器时才迁移（不在 ⇒ 不置位，以后放进来再迁）；物品上已有标记
  ⇒ 以物品为准、旧表丢弃；迁完清空旧表并记一条 INFO；
- `getAreaFilter / addAreaMarker / removeAreaMarker / setAreaMarkerConfig / clearAreaFilter /
  filtersForEntity / hasAnyEffectiveFilter` 全部走 `marksFor`（读）/ `writeMarks`（写，含失效快照 + 标脏）；
- `marksFor` 带**本 tick 缓存**：基类吸收侧按列表**引用相等**给条目分桶（「凑够 N 件」是跨实体累计的），
  同一 tick 内同一区域必须拿到同一个列表对象，否则门槛退化成按单件统计；
- `snapshotFilterIcons(Area)` 改为按**区域几何**查（修掉 ⑤ 的图标串位）；
- `saveAdditional/loadAdditional` 仍写 / 读旧的 `AreaFilters` 键（迁移后可回退观察）。

### 2.3 写通道：`network/AreaMarkEditPacket`（新）+ 落点判据收敛

- 新 C2S 包，三个动作：`ACTION_ADD`（从**玩家背包第 N 格**取物品加一条标记，不消耗）/ `ACTION_REMOVE` /
  `ACTION_CLEAR`。**客户端只发下标，不发明物品 NBT** —— 服务端自己从玩家背包读；
- 落点解析 / 写后同步从 `AreaSelectorEditPacket` 抽到 `support/AreaSelectorTargets`（区域包与标记包
  **共用一份**）：手持 ⇒ 主手选定器；菜单 ⇒ 当前打开 + `stillValid` 的高级仓槽位；其余丢包
  （菜单路径**绝不**回退主手）；
- 校验：旁观者拒绝 + 维度闸门（与区域包同口径）+ **区域必须真的在选定器上**（按六坐标 `indexOfGeometry`）
  + 背包下标越界返回空 + 容量 / 重复检查；
- 区域包在 `DELETE / REBIND` 之后顺手 `AreaMarks.prune(...)`：区域没了，它的标记也一起剪掉。

### 2.4 界面：`client/screen/AreaMarkScreen`（新）

```
┌──────────────────────────────────────────────┐
│ 区域标记 · 刷铁机 · 11 格                     │
│ 本区域的过滤标记        背包（点一下加入）     │
│ [9×4 ghost 格]          [9×4 背包格]          │
│ 左键移除一条            左键加入（不消耗）     │
│ 标记 3 / 288 · 空的区域什么都不吸              │
│            [清空标记]  [返回]                  │
└──────────────────────────────────────────────┘
```

- 左网格 = 该区域已有标记（**左键 = 移除**，工具提示给物品名 + 完整注册 id + 需求数量）；
- 右网格 = 玩家背包镜像（**左键 = 加入**，ghost 不消耗物品；映射：前 3 行 → 背包 9..35，第 4 行 → 快捷栏 0..8）；
- 底部：条数 / 容量（超过 36 条时如实写「界面只列前 36 条，其余在机器界面里看」）、维度不符时**整行红字**
  说明「请先回区域列表点改绑维度」（不让玩家点完以为生效）；
- 不新增任何 GUI 贴图：面板走 `ChildConfigScreen` 的原版九宫格精灵，槽位走 `McGui.slotFrame`
  （逐像素复刻工程既有槽位素材）；tooltip 全部手动渲染；文本先量宽再画。

### 2.5 入口：两处都能进，且都不需要机器

- `AreaSelectorScreen` 的「编辑过滤」改为**直接打开 `AreaMarkScreen`**（手持 / 机器里都行）；
  从机器里打开时仍把 `< >` 上下文切过去，两处状态不打架；
- 主手路径的每行过滤图标改为读 `AreaMarks`（手里拿着选定器也能看到「哪个区域配了什么」）；
- `AreaSelectorHandler` 新增：**不潜行右键空气也打开区域列表**（有未完成的 A 角时仍只提示，避免误开界面）。
  旧入口（潜行 + 右键空气）保留。

## 3. 兼容 / 迁移

- **旧存档**：方块实体上的 `AreaFilters`（序号键）在第一次加载 / 放进选定器时自动迁移到物品几何键；
  迁移前提是槽里真有选定器（否则保留等待）。迁完旧键变空表。
- **旧版本回退**：旧 jar 读新存档 ⇒ 看不到标记（它不认识物品上的 `RsccAreaMarks`），但区域数据完好；
  把选定器拿在手上用新版本重新配一次即可。
- **机器里的 48 格 ghost 窗口行为不变**（含数量门槛 / NBT / 标签细调），只是读写落到物品上；
  两边读写的是同一份数据。

## 5. 未实机验证（如实说明）

- 双网格界面的**实际观感**（间距 / 36 格是否够用）没有在游戏里截图复核；
- 「手持添加 → 机器吸到该物品」的**端到端**链路只在源码 / 模型层验证，没有在实机跑一遍吸收；
- 旧档迁移只在代码路径上验证（`loadAdditional → migrateLegacyAreaFilters`），没有用真实旧存档跑过一次。

下一轮拿到实机反馈后优先处理：① 界面观感与 36 格上限；② 是否需要「数量门槛 / 标签匹配」也能在这个界面里调；
③ 是否需要把「区域标记」做成快捷键入口。
