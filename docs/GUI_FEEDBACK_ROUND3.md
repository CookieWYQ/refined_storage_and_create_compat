## 0. P0 —— 破坏「序列装配样板终端」崩溃

| #   | 现象                                         | 状态   | 说明                                                                       |
| --- | ------------------------------------------ | ---- | ------------------------------------------------------------------------ |
| 0.1 | 破坏方块时游戏崩溃（`UnsupportedOperationException`） | ✅ 已修 | 根因：`GrowingUnitLibrary` 的无上限扩容把 `NonNullList` 当 `ArrayList` 用。见下方 §0 详述。 |

**关键堆栈（crash-2026-09-12\_22.58.13-client.txt）**

```
java.lang.UnsupportedOperationException: null
  at java.base/java.util.AbstractList.remove(AbstractList.java:169)
  at net.minecraft.core.NonNullList.remove(NonNullList.java:83)
  at ...SequencePatternTerminalBlockEntity$GrowingUnitLibrary.rscc$trimTrailingEmpty(...:1130)
  at ...SequencePatternTerminalBlockEntity$GrowingUnitLibrary.serializeNBT(...:1136)
  at ...SequencePatternTerminalBlockEntity.saveAdditional(...:924)
  at net.minecraft.world.level.block.entity.BlockEntity.saveWithoutMetadata(...:114)
  at net.minecraft.world.level.block.entity.BlockEntity.saveWithFullMetadata(...:101)
  at net.neoforged.neoforge.common.util.BlockSnapshot.getBlockEntityTag(...:253)
  at net.neoforged.neoforge.common.util.BlockSnapshot.create(...:70)
  at net.minecraft.client.multiplayer.ClientLevel.setBlock(...:165)
  ... MultiPlayerGameMode.destroyBlock → Minecraft.startAttack（破坏方块）
```

**根因**：`ItemStackHandler` 内部的 `NonNullList` 继承自 `AbstractList`，**不支持 add / remove**；
崩溃版本在 `serializeNBT()` 里先 `trimTrailingEmpty()`（用 `remove` 收缩）再扩容，
而这条序列化路径会被**客户端**触发（`ClientLevel.setBlock → BlockSnapshot.create →
saveWithFullMetadata`），于是「破坏方块」直接崩游戏。

**修复点**（`SequencePatternTerminalBlockEntity.GrowingUnitLibrary`）

1. 收缩改为**整体重建** **`NonNullList`**（`rscc$resize`），彻底不再调用 `remove`；
2. `serializeNBT()` 改为**纯读**：不再修改运行期 `stacks`，直接按「最后一个非空格」构造
   `{Size, Items[{Slot, Item}]}`（与 `ItemStackHandler` 的落盘格式一致，读档用同一套 `deserializeNBT`）。
   序列化从此不可能触发任何结构变更（保存 / 区块快照 / 同步都不会再炸）。

## 1. 匹配 tag —— 语义澄清（最重要）

| #   | 用户原话要点                           | 状态   | 实现                                                                                                                        |
| --- | -------------------------------- | ---- | ------------------------------------------------------------------------------------------------------------------------- |
| 1.1 | 「匹配 tag 是去匹配**一类**物品，不是在一个物品上设置」 | ✅ 已修 | `MarkerEntry` 的布尔 `matchTag` 改为 **`tag`（标签过滤器）**：`markTag != null` 时该条目按 tag 匹配**一整类**资源                                  |
| 1.2 | 「一个物品对应的应该是**匹配 NBT**」           | ✅ 已修 | `matchNbt` 语义收窄为「只针对这一个具体物品的数据组件严格匹配」；与 tag 过滤**互斥**（tag 生效时自动关闭 NBT）                                                     |
| 1.3 | 「我可以**直接增加 tag**，比如过滤所有原木」       | ✅ 已修 | 匹配设置子窗口新增「标签过滤」：填 `minecraft:logs` → 点「应用」即成立（服务端 `SetCollectionTagFilterPacket`，会校验该 tag 下确实有已注册资源，避免空过滤器）；「清除」回到按具体物品匹配 |
| 1.4 | 「不只是子窗口，匹配设置界面的背景也要 MC 那种」       | ✅ 已修 | 子窗口统一走 `ChildConfigScreen` 的原版九宫格面板（见 §4）                                                                                 |

匹配判定（服务端）：

- 物品 tag 过滤器 → `stack.is(TagKey.create(Registries.ITEM, tag))`；

- 流体 tag 过滤器 → `candidate.is(TagKey.create(Registries.FLUID, tag))`；

- 具体物品 → 同物品 + 可选 NBT 严格匹配。
  旧的「与标记物共享任意 tag 就命中」的模糊语义**已删除**（不再混淆两类语义）。
