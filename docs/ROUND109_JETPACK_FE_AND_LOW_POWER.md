# 第 109 轮：电动飞行背包「精确电量显示 + 低电阈值按剩余可飞分钟」

用户第 109 条实机反馈（原话要点，2026-10-31）：

> 「这个电动的背包他的定量要能显示准确的数字，比如说两兆之后也能显示准确数字，不要只显示个 2M。
> 然后它这个电量低究竟在什么时候显示呢？除了我刚刚所说的那个以外，还需要一个阈值：
> 还能飞行多长时间，单位按分钟算，可以配置，预设还能飞 30 分钟。怎么算呢？
> 就直接拿当前电量除以那个配置中的耗电量，然后换算成分钟，再跟人配置的阈值进行对比，
> 小于这个值才提示，否则就不要提示。我他妈现在充了两兆了一直告诉我电量过低。」

本轮只动电动飞行背包的**显示与低电判据**，不碰飞行状态机 / 收回路径 / 耗电口径（第 108 轮已定 8 FE/t）。

---

## 1. 根因：为什么「充了两兆还一直说电量过低」

旧口径是**剩余百分比**：`Config.electricJetpackLowPowerPercent = 10`，
阈值 = `capacity × 10%` = **5000 万 × 10% = 500 万 FE**。

用户充到 200 万 FE（占容量 4%）——按「还能飞多久」算是
`2,000,000 / 8 FE/t = 250,000 tick = 12,500 s ≈ 208 分钟`（3 小时 28 分），
但因为 2,000,000 < 5,000,000，服务端每 30 秒就发一次「电量不足」title。

**结论**：容量 5000 万这个量级下，「剩余百分比」与「还能飞多久」严重脱钩 —— 10% 仍是 500 万 FE，
够飞 8 小时 40 分。判据必须换成**时间**，这也是用户明确给出的口径。

---

## 2. 显示：精确千分位，不再 M/K 缩写

- 新函数 `ElectricJetpackItem.formatFeExact(int)`：`String.format(Locale.ROOT, "%,d", fe)`
  ⇒ `2,000,000` / `50,000,000` / `43,217,456`；固定 `Locale.ROOT`，不受玩家系统语言影响。
- 旧的 `formatFe(int)`（`%.1fM` / `%.1fK`）**整个删除**（不是保留备用），自检里钉死「出现 M/K 缩写即判负」。
- 三处统一用它：
  - **HUD** 第一行：`2,000,000 / 50,000,000 FE`；
  - **物品 tooltip** 电量行：`电量：2,000,000 / 50,000,000 FE`；
  - tooltip 低电阈值行里的阈值 FE 也是精确值。
- 物品栏那条「耐久样式」能量条本来就是按比例，不受影响。

## 3. 低电阈值：剩余可飞分钟（可配置，默认 30）

### 3.1 配置

| 键 | 默认 | 范围 | 说明 |
|---|---|---|---|
| `electricJetpackLowPowerMinutes` | **30** | 1..100000 | 剩余可飞分钟低于它才提示 |

- **旧键 `electricJetpackLowPowerPercent` 彻底移除**（不保留双阈值，避免「到底按哪个」的歧义；
  已写进旧配置文件的键会变成一条无害的未识别项，Minecraft 配置加载会忽略未知键）。
- 配置未加载（读 0）时的安全回退：`DEFAULT_LOW_POWER_MINUTES = 30`，与配置默认值一致。

### 3.2 换算（唯一实现：`ElectricJetpackItem`）

```
TICKS_PER_MINUTE      = 20 tick/s × 60 s = 1200
lowPowerThresholdFe() = lowPowerMinutes() × 1200 × flightCost()        // long 运算，防 int 溢出
remainingFlightMinutes(energy) = max(0, energy) / flightCost() / 1200  // 向下取整
```

- 默认值代入：`30 × 1200 × 8 = 288,000 FE` —— 这就是默认配置下的低电阈值电量。
- 判据：**严格小于**（`energyAfter < threshold`）。剩余正好 30 分钟不提示，29 分 59 秒才提示；
  用户口径「小于这个值才提示」逐字落地。
- `remainingFlightMinutes` 是 HUD / tooltip / 低电副标题**共用**的函数，三处数字不会互相矛盾。

### 3.3 用户场景逐例（默认 30 分钟 / 8 FE/t）

| 电量 | 剩余可飞 | 是否提示 |
|---|---|---|
| 50,000,000（满） | 5208 分钟 | 不提示 |
| **2,000,000（用户「充了两兆」）** | **208 分钟** | **不提示**（修复后） |
| 288,000（正好 30 分钟） | 30 分钟 | 不提示（严格小于） |
| 287,992（29 分 59 秒） | 29 分钟 | 提示 |
| 192,000（20 分钟） | 20 分钟 | 提示 |
| 0 | 0 分钟 | 提示（且飞行已被收回） |

### 3.4 提示文案

- 低电 title：`电量不足` + **副标题** `剩余可飞约 28 分钟`（原版 `ClientboundSetSubtitleTextPacket`）。
  新增语言键 `item.rs_create_compat.electric_jetpack.low_power.subtitle`。
- 触发器其余口径不变（第 105 轮）：**只在真的在飞**（`abilities.flying`）时发；跨阈值一次 +
  持续低电每 30 秒至多一条；落地不清「已提示」状态。

## 4. HUD：第三行直接写出剩余分钟

```
┌──────────────────────────────────────────┐
│ [████████░░░░] 2,000,000 / 50,000,000 FE │
│ 范围内 · 充电中                            │
│ 剩余可飞约 208 分钟（低于阈值时变红）        │
└──────────────────────────────────────────┘
```

- 新增语言键 `item.rs_create_compat.electric_jetpack.hud.flight_left`。
- 低于低电阈值时该行颜色从 `#A8C7D8` 变 `#FF7B72`（与低电 title 呼应）——
  玩家不用打开 tooltip 就知道「现在还剩多久、为什么还没提示 / 为什么提示了」。
- panel 宽度按三行最宽的一行算，高度多一行。

## 5. tooltip：写出剩余分钟与阈值说明

- `item.rs_create_compat.electric_jetpack.tooltip.flight_left` = `剩余可飞约 %s 分钟`
- `item.rs_create_compat.electric_jetpack.tooltip.low_power` =
  `低电提示：剩余可飞少于 %s 分钟（%s FE）时才提示` —— 玩家能自己核对「为什么现在没提示」。

## 7. 未实机验证的部分（如实交代）

- 「两兆不再提示」由**行为模型**证明（同一套公式 + 边界逐例），没有在真实世界飞 3 小时；
- HUD 第三行的观感（面板变高一点、低电变红的可辨识度）只有几何推算，没有截图；
- 若玩家把 `electricJetpackFlightCostPerTick` 调得很大，阈值 FE 会随之变大（这是公式的自然结果）：
  例如 1000 FE/t 时 30 分钟 = 1800 万 FE，此时满电也只能飞 50 分钟，按分钟判定会一直提示 ——
  这正是「按时间判定」的语义（不是 bug），tooltip 会显示实时阈值 FE 供核对。
