# 界面文本「完整显示」规则（第 104 轮，用户口径落地）

> 用户原话：**「所有的这个界面的文本如果可以的话尽量全部都不要出现…（省略号），所有都尽量保持全部显示完成，
> 尽可能是更改他的那个排列方式而不是搞这个破…」**
>
> 翻译成可执行规则：**客户端界面里任何地方都不允许出现 `"..."` 省略/截断**；
> 空间不够时优先**改排列**，而不是把文字截短。

## 1. 落地手段的优先级（从上到下依次尝试）

| 顺序 | 手段 | 说明 |
| --- | --- | --- |
| 1 | **改排列** | 折行（两行/多行）、「标签 + 值」拆两段、把长值换到下一行、重新分组、右对齐、把次要说明挪到悬浮 tooltip 而主行完整显示关键信息。**这是首选。** |
| 2 | **缩短静态文案** | 只改 `lang` 里该键的**值**（键不变）。中文 ≤ 12 字、英文 ≤ 5 词是工程既有纪律。新 zh/en 原文**列给 Lead 落盘**，teammate 不直接改 lang 文件。 |
| 3 | **缩小字号** | 用 `RsccTextFit.drawFitLine` / `drawFitBlock`，下限 0.6 倍。只在纵向确实没有折行空间、文案又是自由文本时用。 |
| 4 | **悬浮 tooltip 兜底** | 主行显示完整可读的短文本，完整值（玩家命名 / 第三方模组超长名）放进 hover tooltip。tooltip 内同样**不得**省略。 |

## 2. 唯一工具：`client/widget/RsccTextFit.java`

| API | 用途 |
| --- | --- |
| `fitsLine(font, text, maxWidth)` | 单行放得下吗（不缩字号） |
| `fitsBlock(font, text, maxWidth, maxLines)` | 在 N 行内折得下吗 |
| `lineCount(font, text, maxWidth)` | 折行后行数 |
| `requiredScaleForLine(font, text, maxWidth)` | 单行完整显示所需缩放；返回值 < 0.6 ⇒ 必须走 tooltip 兜底 |
| `drawFitLine(...)` | 单行完整显示（放不下就缩，**绝不省略**） |
| `drawFitBlock(..., maxLines, lineHeight, ...)` | 折行完整显示；行数超限时逐档缩字号重新折行；返回占用高度 |

**禁止**自己再造一套「按宽度截断」的私有方法；已有的 `trimToWidth` / `truncate` / `cutToWidth` 一律删除。

## 3. 禁止的源码模式（`tools/selfcheck_no_ellipsis.py` 会判负）

1. 客户端源码里出现字符串字面量 `"..."`（注释里的说明文字不算，selfcheck 会剥注释后判定）；
2. 任何 `while (... font.width(...) ...)` 形式的「逐字符缩到放得下」循环；
3. 任何以截断为职责的私有方法定义（`trimToWidth` / `truncate` / `cutToWidth` / `fitToWidth`）；
4. `substring(0, ...)` 后接省略号拼接。

## 4. 判定与验收

- **中英都要完整显示**：以**英文**宽度为准（英文通常更长）。
- 文字**不得越出面板边界**、不得压到槽位 / 按钮 / 读数板 / 高光线。
- 每处改完在回报里给出：`file:line`（原截断点）→ 新排布（画在哪、占几行、实测 zh/en 宽度 vs 可用宽度）。
- 自由文本（第三方模组名字）确实无法在面板内完整显示时：主行完整显示可读部分（**不省略**，缩到 0.6 为止），
  完整原文放 tooltip；并在回报的「未验证项」里如实写明这一处是缩字号还是 tooltip 兜底。

## 5. 不做的事

- **不改 GUI 背景 PNG 的尺寸 / 槽位网格**（背景是固定尺寸素材，改尺寸要连 `Menu.addSlot`、`imageWidth/Height`、
  既有自检一起动，属于另一轮的活）。若某界面确实需要更大的面板才能放下完整文本，列给 Lead 评估。
- **不改 `lang/*`**（Lead 写域）。
